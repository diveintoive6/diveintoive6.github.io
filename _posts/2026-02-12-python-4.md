파이썬을 다루다 보면 문자열 메서드의 동작 방식이나 객체의 가변성에 발목을 잡히는 경우가 종종 있습니다. 특히 "메서드를 썼는데 원본이 바뀌나?", "복사했는데 왜 값이 같이 바뀌지?" 같은 의문은 파이썬을 깊이 있게 이해하기 위해 반드시 짚고 넘어가야 할 핵심 주제입니다.

이번 글에서는 **`find()` 메서드의 특징**부터 **참조 vs 실제 복사 개념**, 그리고 **가변성에 따른 원본 변경 여부**까지 명확하게 정리해 보겠습니다.

## 1. 문자열 검색: `find()`의 반환값과 함정

파이썬에서 문자열 내에 특정 문자나 문자열이 있는지 찾을 때 **`find()`** 메서드를 사용합니다.

### 📌 `find()`의 반환값 규칙
* **찾은 경우:** 해당 문자열이 시작하는 **인덱스 번호**를 반환합니다.
* **못 찾은 경우:** **`-1`**을 반환합니다. (절대 나올 수 없는 인덱스 번호 -1을 실패 신호로 사용)

```python
s = "hello world"

print(s.find("world"))   # 출력: 6 (시작 인덱스)
print(s.find("python"))  # 출력: -1 (없음)

```

### ⚠️ 실무에서 가장 자주 하는 실수 (`0`의 함정)

만약 찾으려는 문자열이 맨 처음에 있어서 인덱스가 `0`이 나오면 조건문에서 문제가 생길 수 있습니다.

```python
s = "hello world"

# ❌ 잘못된 사용 (인덱스 0은 파이썬에서 False로 취급됨!)
if s.find("hello"):
    print("찾았다!")  # 실행되지 않음! (0 == False)

# ✅ 올바른 사용 1: 명시적 비교
if s.find("hello") != -1:
    print("찾았다!")  # 정상 실행

# ✅ 올바른 사용 2 (더 파이써닉한 방법): in 키워드 사용
if "hello" in s:
    print("찾았다!")  # 가장 직관적이고 안전함

```

### 💡 `find()` vs `index()` 차이점

* **`find()`**: 찾는 문자열이 없으면 `-1` 반환
* **`index()`**: 찾는 문자열이 없으면 `ValueError` 예외(에러) 발생

## 2. 문자열의 `replace()`: 원본이 바뀔까?

결론부터 말하면, **원본 문자열은 절대 바뀌지 않습니다.**

```python
s = "hello"
s.replace("h", "j")

print(s)  # 출력: "hello" (원본 유지)

```

### 🔍 이유: 문자열은 불변(Immutable) 객체이기 때문

파이썬의 문자열(`str`), 정수(`int`), 튜플(`tuple`) 등은 **불변 객체**입니다. 즉, 생성된 이후에 그 값을 내부적으로 수정할 수 없습니다.

* `replace()` 메서드는 원본을 고치는 것이 아니라, **변경된 내용이 적용된 "완전히 새로운 문자열 객체"를 만들어서 반환**할 뿐입니다.
* 따라서 결과를 반영하려면 반환값을 다시 변수에 대입해야 합니다.

```python
s = "hello"
s = s.replace("h", "j")  # 새로운 객체를 다시 대입
print(s)  # 출력: "jello"

```

## 3. 참조(Reference) vs 실제 복사 (가변성과 복사의 모든 것)

객체가 가변(Mutable, 예: 리스트, 딕셔너리)이냐 불변(Immutable)이냐에 따라 대입(참조)과 복사(`copy`, `deepcopy`)의 동작이 완전히 달라집니다.

### 📌 개념 요약

* **참조 (대입 `=`)**: 객체는 하나인데, 가리키는 이름(변수)만 늘어나는 것 (주소 공유)
* **얕은 복사 (Shallow Copy)**: 겉 박스만 새로 만들고, 안의 내부 객체(참조)는 그대로 공유하는 것
* **깊은 복사 (Deep Copy)**: 겉 박스부터 안쪽의 모든 객체까지 완전히 새 것으로 복사하여 독립시키는 것

---

### ① 가변 객체(리스트)의 대입 vs 복사

```python
# 1. 단순 대입 (참조 공유)
a = [1, 2, 3]
b = a          # b는 a와 똑같은 리스트 객체를 가리킴
b.append(4)

print(a)       # 출력: [1, 2, 3, 4]  -> b를 바꿨는데 a도 바뀜!

```

```python
# 2. 얕은 복사 (Shallow Copy) - 1차원 구조는 안전하지만 중첩에서 깨짐
import copy

a = [[1, 2], [3, 4]]
b = a.copy()   # 또는 a[:]

b[0].append(99)
print(a)       # 출력: [[1, 2, 99], [3, 4]] -> 안쪽 리스트가 공유되어 a까지 변경됨!

```

```python
# 3. 깊은 복사 (Deep Copy) - 완전히 독립된 객체 생성
import copy

a = [[1, 2], [3, 4]]
b = copy.deepcopy(a)

b[0].append(99)
print(a)       # 출력: [[1, 2], [3, 4]] -> a는 전혀 영향 받지 않음! 완벽 분리!

```

## 4. 한눈에 보는 비교 표

| 구분 | 불변 객체 (`str`, `int`, `tuple`) | 가변 객체 (`list`, `dict`, `set`) |
| --- | --- | --- |
| **특징** | 값을 바꿀 수 없음 (새 객체 생성) | 값을 내부에서 직접 수정 가능 |
| **대입 (`b = a`)** | 값 변경 시 어차피 각자 다른 객체를 보게 됨 | 같은 객체를 바라보므로 **한쪽을 바꾸면 양쪽 다 바뀜** |
| **얕은 복사 (`copy`)** | 불필요 (불변이라 공유해도 안전함) | 겉 껍데기는 복사되나, **중첩된 가변 객체는 공유됨** |
| **깊은 복사 (`deepcopy`)** | 불필요 | **내부까지 완전히 독립된 새 객체 생성** |

---

## ✨ 핵심 요약

1. **`s.find()`**: 문자열이 없으면 `-1`을 반환하므로, 조건문에서 `0`(`False`) 처리에 주의하고 안전하게 `in` 연산자를 활용하자.
2. **`s.replace()`**: 문자열은 불변(immutable)이므로 원본은 안 바뀌고 **새 문자열을 반환**한다.
3. **가변 객체(`list` 등)**: 단순 대입(`=`)이나 얕은 복사(`copy`)를 쓰면 내부 데이터가 같이 변경될 수 있으므로, 중첩 구조에서는 깊은 복사(`copy.deepcopy`)를 적극 활용하자.
