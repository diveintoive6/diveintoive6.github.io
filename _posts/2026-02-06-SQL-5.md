파이썬(`pymysql`)과 MySQL을 연동하여 데이터를 저장하고 불러오는 기본적인 세팅을 마쳤다면, 그다음으로 가장 많이 마주하는 관문은 바로 데이터를 조회하는 **`SELECT`** 문입니다. 

실무에서 데이터를 조회할 때 헷갈리기 쉬운 개념과 `GROUP BY`, 집계 함수 등 반드시 알아야 할 핵심 포인트 5가지를 정리해 보았습니다.

---

## 0. 시작 전 기본 코드 확인

파이썬에서 `pymysql`을 통해 MySQL에 접속하고 데이터를 가져오는 기본 뼈대는 다음과 같습니다. 이 뼈대 위에 다양한 `SELECT` 쿼리를 얹어서 사용하게 됩니다.

```python
import pymysql

# 1. DB 연결
mysql = pymysql.connect(
    host="127.0.0.1",
    port=9090,
    user="ive",
    passwd="root",
    db="myschool",
    charset="utf8mb4",
    use_unicode=True
)

cursor = mysql.cursor()

# 한글 깨짐 방지 세션 설정
cursor.execute("SET NAMES utf8mb4")

# 2. 쿼리 실행 및 결과 처리
cursor.execute("SELECT * FROM student;")
column_names = [col[0] for col in cursor.description]  # 칼럼명 추출
result = cursor.fetchall()  # 데이터 전체 가져오기

print("칼럼명:", column_names)
for row in result:
    print(row)

# 3. 연결 종료
mysql.close()

```

---

## 1. 파이썬에서 조회 결과를 다루는 방법 (`fetchall` vs `fetchone`)

데이터베이스에서 쿼리를 실행한 뒤 파이썬으로 가져올 때 사용하는 메서드의 차이를 정확히 알고 있어야 합니다.

* **`cursor.fetchall()`**: 조회된 모든 행(Row)을 튜플 형태로 한꺼번에 가져옵니다. 데이터가 너무 많을 경우 메모리를 많이 차지할 수 있습니다.
* **`cursor.fetchone()`**: 조회된 결과 중 **가장 첫 번째 행 1개**만 가져옵니다. 호출할 때마다 그다음 행으로 커서가 이동합니다.
* **`cursor.fetchmany(size)`**: 지정한 개수(예: 100개) 만큼만 끊어서 가져올 때 사용합니다. 대용량 데이터를 처리할 때 메모리 보호를 위해 유용합니다.

---

## 2. SQL 실행 순서와 WHERE, ORDER BY, LIMIT의 조합

SQL 쿼리를 작성할 때 작성하는 순서와, 실제로 컴퓨터가 실행하는 순서는 다릅니다. 이 순서의 차이 때문에 헷갈리는 경우가 많습니다.

* **작성 순서:** `SELECT` ➔ `FROM` ➔ `WHERE` ➔ `GROUP BY` ➔ `HAVING` ➔ `ORDER BY` ➔ `LIMIT`
* **실행 순서:** `FROM` (테이블 확인) ➔ `WHERE` (조건에 맞는 행 필터링) ➔ `GROUP BY` (그룹화) ➔ `HAVING` (그룹 조건 필터링) ➔ `SELECT` (조회할 칼럼 선택) ➔ `ORDER BY` (정렬) ➔ `LIMIT` (개수 제한)

> 💡 **자주 하는 실수:** `WHERE` 절에서는 집계 함수(`SUM`, `COUNT` 등)를 사용할 수 없습니다. 집계 함수는 `WHERE`가 처리된 *후*에 동작하기 때문입니다.

---

## 3. 집계 함수와 GROUP BY (그룹화의 짝꿍)

데이터를 전체로 보는 것이 아니라, 특정 카테고리별로 묶어서 통계를 내고 싶을 때 사용하는 것이 바로 `GROUP BY`와 집계 함수(`COUNT`, `SUM`, `AVG`, `MAX`, `MIN`)입니다.

* **예시 상황:** 학급별 학생 수나, 부서별 평균 급여를 구할 때 필수적입니다.
* **SQL 쿼리 예시:**
```sql
-- 학년(grade)별 학생 수와 평균 점수를 조회
SELECT grade, COUNT(*) AS student_count, AVG(score) AS avg_score
FROM student
GROUP BY grade;

```


* **파이썬 연동 시 주의점:** `GROUP BY`를 쓰면 원본 데이터의 행 개수가 줄어들고 그룹별 요약본만 반환되므로, 파이썬에서 `fetchall()`로 받을 때 칼럼 구조가 어떻게 바뀌는지 `cursor.description`으로 꼭 확인해야 합니다.

---

## 4. WHERE vs HAVING (조건 필터링의 위치 차이)

초보자들이 가장 많이 헷갈리고 실수하는 부분 중 하나입니다. 둘 다 조건을 거는 역할이지만 **적용되는 시점**이 다릅니다.

* **`WHERE`**: 데이터를 **그룹화하기 전**에 개별 행을 필터링합니다. (일반 조건)
* **`HAVING`**: 데이터를 **그룹화한 후**에 집계된 결과에 대해 필터링합니다. (그룹 집계 조건)

```sql
-- [오류 발생 예시] WHERE에서는 집계 함수 사용 불가
SELECT grade, COUNT(*) 
FROM student 
WHERE COUNT(*) >= 5 
GROUP BY grade;

-- [정상 동작] 집계 후의 조건은 반드시 HAVING 사용
SELECT grade, COUNT(*) AS cnt
FROM student 
GROUP BY grade
HAVING cnt >= 5;

```

## 5. 파이썬 연동 시 절대 금물: SQL 인젝션 방지와 파라미터 바인딩

파이썬에서 `SELECT` 쿼리를 날릴 때 사용자 입력값(예: 검색어, 아이디)을 변수로 넣기 위해 파이썬의 f-string이나 문자열 포맷팅을 쓰기 쉽습니다. 하지만 이는 **SQL 인젝션(SQL Injection)** 보안 공격에 매우 취약합니다.

* **잘못된 방식 (보안 취약):**
```python
# 절대 이렇게 문자열 직접 결합을 쓰면 안 됩니다!
keyword = "김철수"
cursor.execute(f"SELECT * FROM student WHERE name = '{keyword}'")

```


* **올바른 방식 (파라미터 바인딩):**
`pymysql`이 제공하는 튜플 형태의 파라미터 바인딩 기능을 사용해야 안전합니다.
```python
keyword = "김철수"
# 쿼리 안에는 %s를 사용하고, 뒤에 튜플로 변수를 전달합니다.
sql = "SELECT * FROM student WHERE name = %s"
cursor.execute(sql, (keyword,))

result = cursor.fetchall()

```



---

## 💡 요약

* 파이썬으로 데이터를 가져올 때는 `fetchall()`과 `fetchone()`의 차이를 용도에 맞게 선택하자.
* 조건에 집계 함수가 포함된다면 `WHERE`가 아니라 `HAVING`을 써야 한다.
* 파이썬 변수를 쿼리에 넣을 때는 f-string 대신 **`%s` 파라미터 바인딩**을 생활화하자.
