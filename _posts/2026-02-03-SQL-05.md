이번 포스팅에서는 테이블의 데이터를 수정하고 삭제하는 명령어인 **UPDATE**와 **DELETE**, 그리고 관계형 데이터베이스의 꽃이라 불리는 여러 테이블 연결 기술 **JOIN** (INNER JOIN, OUTER JOIN, EQUI JOIN, CROSS JOIN, SELF JOIN)에 대해 실전 활용 예제 10선을 포함하여 정리해 보겠습니다.

---

## 1. 데이터 수정 및 삭제 (UPDATE, DELETE)

### ① UPDATE 문 (데이터 수정)
기존에 저장된 테이블의 데이터를 변경할 때 사용합니다.
```sql
UPDATE 테이블이름
SET 컬럼1 = 값1,
    컬럼2 = 값2
[WHERE 조건];

```

* **주의사항**: `WHERE`절을 생략할 경우 **테이블의 모든 행**이 수정되므로 매우 주의해야 합니다.

### ② DELETE 문 (데이터 삭제)

테이블에서 행을 삭제할 때 사용합니다.

```sql
DELETE FROM 테이블이름 
[WHERE 조건];

```

* **주의사항**: `WHERE`절을 생략하면 **테이블의 모든 데이터가 삭제**됩니다. 실무에서는 주로 기본키(Primary Key)를 조건으로 지정하여 특정 데이터만 안전하게 삭제합니다.

---

## 2. JOIN의 이해와 종류

관계형 데이터베이스에서 두 개 이상의 테이블을 연결하여 관련 데이터를 하나의 결과 집합으로 조회하는 방법입니다. 공통된 컬럼(주로 외래 키와 기본키)을 기준으로 연결합니다.

### 주요 JOIN 종류

| JOIN 종류 | 설명 | 비고 |
| --- | --- | --- |
| **INNER JOIN** | 양쪽 테이블 모두에 일치하는 행만 반환 (교집합) | 가장 기본적이고 빈번하게 사용 |
| **LEFT [OUTER] JOIN** | 왼쪽 테이블 전체 + 오른쪽 테이블에서 일치하는 행 (불일치 시 NULL) | - |
| **RIGHT [OUTER] JOIN** | 오른쪽 테이블 전체 + 왼쪽 테이블에서 일치하는 행 (불일치 시 NULL) | - |
| **EQUI JOIN** | WHERE 절을 통해 두 테이블의 일치 조건을 명시한 조인 | INNER JOIN과 결과 동일 |
| **CROSS JOIN** | 두 테이블의 모든 조합 반환 (카테시안 곱) | 조건 없이 모든 경우의 수 생성 |
| **SELF JOIN** | 자기 자신을 두 번 참조하여 조인 (별칭 활용) | 계층 구조나 내부 비교에 사용 |

## 3. 세부 JOIN 문법 구조

### ① INNER JOIN 기본 구문

```sql
SELECT 컬럼이름
FROM 주제테이블 AS a
INNER JOIN 대상테이블 AS b ON a.참조키 = b.기본키
[ WHERE 검색조건 ];

```

* 예약어 `ON` 뒤에 연결 조건을 명시합니다. (`INNER` 키워드는 생략 가능)

### ② OUTER JOIN 기본 구문

```sql
SELECT 컬럼이름
FROM 주제테이블 AS a
LEFT | RIGHT OUTER JOIN 대상테이블 AS b ON a.참조키 = b.기본키
[ WHERE 검색조건 ];

```

* 기준이 되는 방향의 모든 데이터는 조건 불일치 시에도 `NULL`로 채워져 유지됩니다. (`OUTER` 생략 가능)

### ③ EQUI JOIN & CROSS JOIN

* **EQUI JOIN**: `FROM`절에 콤마(`,`)로 여러 테이블을 나열하고 `WHERE`절에 조인 조건을 작성합니다.
* **CROSS JOIN**: 조건 없이 모든 조합을 반환하며, 대용량 데이터 시 시스템 부하에 주의해야 합니다.

### ④ SELF JOIN

하나의 테이블에 두 개의 서로 다른 별칭(`alias`)을 부여하여 마치 두 개의 서로 다른 테이블인 것처럼 조인합니다.

* **주요 용도**: 상위-하위 구조(조직도, 직원-상사), 같은 집단 내 비교 등

## 4. 실전 활용 예제 10선

### 예제 1: 회원 연락처 정보 수정 (`UPDATE`)

특정 회원의 전화번호와 이메일 주소를 새로운 값으로 변경합니다.

```sql
UPDATE users
SET phone = '010-9999-8888', email = 'new_hong@example.com'
WHERE user_id = 101;

```

### 예제 2: 탈퇴 회원 데이터 삭제 (`DELETE`)

회원 상태가 'WITHDRAWN'이고 마지막 접속일이 오래된 계정을 삭제합니다.

```sql
DELETE FROM users
WHERE status = 'WITHDRAWN' AND last_login_date < '2025-01-01';

```

### 예제 3: INNER JOIN을 활용한 교수와 소속 학과 조회

교수 테이블(`professors`)과 학과 테이블(`departments`)을 연결하여 교수의 이름과 소속 학과명을 함께 조회합니다.

```sql
SELECT p.professor_name, d.department_name
FROM professors AS p
INNER JOIN departments AS d ON p.department_id = d.id;

```

### 예제 4: LEFT OUTER JOIN을 활용한 전체 학생 및 수강 내역 조회

학생 테이블 전체를 기준으로, 수강 신청 내역이 없는 학생까지 빠짐없이 조회합니다.

```sql
SELECT s.student_name, e.course_id
FROM students AS s
LEFT OUTER JOIN enrollments AS e ON s.student_id = e.student_id;

```

### 예제 5: EQUI JOIN 방식을 이용한 주문 정보 조회

전통적인 `WHERE`절 조인 방식을 사용하여 고객 정보와 주문 정보를 결합합니다.

```sql
SELECT c.customer_name, o.order_id, o.order_date
FROM customers AS c, orders AS o
WHERE c.customer_id = o.customer_id;

```

### 예제 6: CROSS JOIN을 통한 상품 사이즈와 색상 모든 조합 생성

의류 상품의 모든 사이즈(`S, M, L`)와 컬러(`Red, Blue`) 조합을 카테시안 곱으로 생성합니다.

```sql
SELECT s.size_name, c.color_name
FROM sizes AS s
CROSS JOIN colors AS c;

```

### 예제 7: SELF JOIN을 이용한 상사-직원 관계 조회

직원 테이블(`employees`)에서 사원과 직속 상관(`manager_id`)의 이름을 함께 조회합니다.

```sql
SELECT e1.employee_name AS staff_name, 
       e2.employee_name AS manager_name
FROM employees AS e1
LEFT JOIN employees AS e2 ON e1.manager_id = e2.employee_id;

```

### 예제 8: INNER JOIN과 집계 함수의 결합 (부서별 평균 급여)

직원 테이블과 부서 테이블을 조인한 뒤, 부서별 평균 급여를 계산하여 출력합니다.

```sql
SELECT d.department_name, ROUND(AVG(e.salary), 2) AS avg_salary
FROM employees AS e
INNER JOIN departments AS d ON e.department_id = d.id
GROUP BY d.department_name;

```

### 예제 9: 다중 테이블 JOIN (고객, 주문, 상품 정보 결합)

세 개 이상의 테이블을 `INNER JOIN`으로 연결하여 누가 어떤 상품을 주문했는지 종합적으로 조회합니다.

```sql
SELECT c.customer_name, p.product_name, o.quantity, o.order_date
FROM orders AS o
INNER JOIN customers AS c ON o.customer_id = c.customer_id
INNER JOIN products AS p ON o.product_id = p.product_id;

```

### 예제 10: OUTER JOIN과 조건 필터링 (주문 내역이 없는 휴면 고객 찾기)

`LEFT OUTER JOIN`을 활용해 주문 이력이 전혀 없는(`NULL`인) 고객을 찾아냅니다.

```sql
SELECT c.customer_name, c.email
FROM customers AS c
LEFT JOIN orders AS o ON c.customer_id = o.customer_id
WHERE o.order_id IS NULL;

```

## 5. 마무리 요약

* `UPDATE`와 `DELETE`를 사용할 때는 데이터 유실을 방지하기 위해 **반드시 `WHERE`절 조건을 확인**해야 합니다.
* **JOIN**은 관계형 데이터베이스의 핵심으로, 일치하는 데이터만 가져오는 `INNER JOIN`과 한쪽의 전체 데이터를 보존하는 `OUTER JOIN`을 상황에 맞게 선택하여 활용해야 합니다.
* 자기 자신을 참조하는 `SELF JOIN`을 익혀두면 계층형 데이터를 다룰 때 매우 강력한 무기가 됩니다.
