## 1. 테이블 생성 및 컬럼 데이터 타입

### ① 테이블 생성 구문 기본 구조
데이터베이스 내에 데이터를 저장할 표 형태의 공간을 정의합니다.
```sql
CREATE TABLE [IF NOT EXISTS] 테이블이름 (
    컬럼이름1 데이터타입 [제약조건] [COMMENT '컬럼설명'],
    컬럼이름2 데이터타입 [제약조건] [COMMENT '컬럼설명'],
    [PRIMARY KEY (컬럼이름)],
    [FOREIGN KEY (컬럼이름) REFERENCES 부모테이블(컬럼)]
) [DEFAULT CHARSET=문자셋] [COLLATE=콜레이션] [COMMENT='테이블설명'];

```

* **네이밍 컨벤션**: 테이블 이름은 복수형, 컬럼 이름은 단수형으로 지정하는 것을 권장합니다.
* **안전 장치**: `IF NOT EXISTS`를 추가하여 동일한 이름의 테이블이 이미 존재할 때 발생하는 에러를 방지합니다.
* **COMMENT 활용**: 테이블과 컬럼에 설명을 남겨두면 나중에 명세서 자동 생성 및 협업에 매우 유리합니다.

### ② 컬럼의 데이터 타입 (도메인 무결성 제약)

데이터를 저장할 때 알맞은 유형을 선택해야 시스템 자원을 효율적으로 쓰고 무결성을 지킬 수 있습니다.

* **정수형 데이터 타입**
* `TINYINT`: 아주 작은 정수 (1바이트, 예: 평점, 상태 코드)
* `SMALLINT`: 작은 정수 (2바이트, 예: 재고 수량)
* `INT` / `INTEGER`: 일반적인 정수 (4바이트, 예: 회원번호, 상품가격)
* `BIGINT`: 아주 큰 정수 (8바이트, 예: 결제 트랜잭션 ID, 누적 포인트)


* **실수형 데이터 타입**
* `FLOAT` / `DOUBLE`: 부동소수점 방식 (예: 할인율, 위도/경도)
* `DECIMAL(p,s)`: 정확한 고정소수점 방식 (예: 금융 계산, 환율)


* **문자열 데이터 타입**
* `CHAR(n)`: 고정 길이 문자열 (공간이 고정됨)
* `VARCHAR(n)`: 가변 길이 문자열 (입력된 데이터 크기에 맞춤, 예: 이름, 이메일)
* `TEXT`: 긴 텍스트 (장문 설명, 후기)
* `ENUM`: 정해진 문자열 목록 중 하나만 선택 (예: 성별, 주문 상태)


* **날짜 및 시간형 데이터 타입**
* `DATE`: 날짜만 저장 (`YYYY-MM-DD`)
* `DATETIME`: 날짜와 시간 모두 저장 (`YYYY-MM-DD HH:MM:SS`)
* `TIME`: 시간만 저장 (`HH:MM:SS`)


* **논리형 (BOOLEAN)**
* 참(1)과 거짓(0)을 표현 (예: 회원 활성 여부)



### ③ 컬럼 제약 조건 (Constraints)

* `NOT NULL`: `NULL` 값 저장을 금지하여 반드시 값이 입력되도록 강제합니다.
* `DEFAULT`: 값을 입력하지 않았을 때 자동으로 지정될 기본값을 설정합니다. (`DEFAULT CURDATE()` 등 활용 가능)
* `UNIQUE`: 컬럼에 중복된 값이 들어오는 것을 방지합니다.
* `PRIMARY KEY`: 테이블의 각 행을 고유하게 식별하는 기본 키 (중복 불가, `NOT NULL`).
* `AUTO_INCREMENT`: 숫자를 자동으로 1씩 증가시켜 레코드가 추가되도록 합니다.

## 2. 데이터베이스 설계 단계 (데이터 모델링과 ERD)

데이터베이스를 구축하기 전, 비즈니스 요구사항을 분석하고 구조를 체계화하는 과정을 **데이터 모델링**이라고 합니다.

### 데이터 모델링 3단계

1. **개념적 모델링 (Conceptual Modeling)**
* 비즈니스 프로세스를 분석하고 업무 전체의 핵심 데이터 구조를 추상화합니다.
* 기술적 용어를 지양하고 엔터티(Entity)와 속성(Attribute)을 도출하여 개념적 ERD를 작성합니다.


2. **논리적 모델링 (Logical Modeling)**
* 개념적 모델을 바탕으로 식별자를 도출하고 모든 릴레이션을 정의합니다.
* 정규화(Normalization)를 수행하여 데이터의 독립성을 확보하고 중복을 제거합니다.


3. **물리적 모델링 (Physical Modeling)**
* 특정 DBMS(MariaDB, MySQL 등)에 종속된 실제 구조를 설계합니다.
* 속성을 컬럼으로 바꾸고 정확한 데이터 타입, 제약조건, 성능, 보안 요소를 고려합니다. *(※ 실무에서는 개념·논리 단계를 약식으로 거치거나 물리적 모델링 바로 진행하는 경우도 많습니다.)*



### ERD (Entity Relationship Diagram)의 구성 요소

* **Entity (개체)**: 저장할 데이터의 단위 (테이블, 네모 박스로 표현)
* **Attribute (속성)**: 개체가 가지는 상세 정보 (컬럼)
* **Relationship (관계)**: 개체 간의 연관성 (외래키 기반 연결)

## 3. DBML (Database Markup Language)

DBML은 데이터베이스 구조(Schema)를 가볍고 읽기 쉬운 텍스트 파일로 정의할 수 있는 마크업 언어입니다.

* **장점**: Git 등을 통한 형상관리(Version Control)가 용이하고, 마크업 코드를 통해 자동으로 ERD 시각화 도구와 연동할 수 있습니다.
* **주요 문법 형식**:
* 테이블 정의 시 컬럼과 제약 조건을 대괄호(`[...]`) 안에 쉼표로 구분하여 표기합니다.
* `id int [pk, increment]` (기본키 및 자동 증가)
* `status varchar(10) [default: "active"]` (기본값 설정 시 쌍따옴표 주의)
* `email varchar(150) [unique, note: "사용자 이메일"]` (제약 조건과 설명 함께 표기)


* 열거형 데이터는 `Enum` 블록으로 정의하여 데이터 타입처럼 활용할 수 있으며, 참조키(`ref: > 부모테이블.기본키`)를 통해 테이블 간 관계를 간결하게 표현합니다.

## 4. 트랜잭션(Transaction)과 ACID 특성

### 트랜잭션의 개념

하나의 데이터베이스에서 논리적인 작업 단위를 이루는 일련의 SQL 묶음입니다. 여러 개의 SQL이 실행될 때, 모두 성공하거나 모두 취소(All or Nothing)되어야 데이터의 불일치 현상을 막을 수 있습니다.

### 트랜잭션의 4대 특성 (ACID)

| 특성 | 의미 | 설명 |
| --- | --- | --- |
| **Atomicity (원자성)** | All or Nothing | 트랜잭션 내의 모든 연산은 완전히 반영되거나 전혀 반영되지 않아야 함 |
| **Consistency (일관성)** | Integrity 유지 | 트랜잭션 전후로 데이터베이스의 무결성 제약 조건이 항상 유지되어야 함 |
| **Isolation (격리성)** | 독립 실행 | 동시에 실행되는 여러 트랜잭션들이 서로 간섭하거나 영향을 주지 않아야 함 |
| **Durability (지속성)** | 영속성 | 성공적으로 완료된 트랜잭션의 결과는 시스템이 멈추어도 영구적으로 저장되어야 함 |

### 주요 트랜잭션 제어 명령어

* `START TRANSACTION;`: 트랜잭션의 시작을 선언합니다.
* `COMMIT;`: 트랜잭션 내의 모든 작업 내용을 데이터베이스에 영구적으로 확정합니다.
* `ROLLBACK;`: 오류 발생 시 트랜잭션 내에서 수행했던 변경 사항들을 모두 취소하고 이전 상태로 되돌립니다.
* `SAVEPOINT 이름;`: 트랜잭션 도중 특정 지점에 이름을 붙여 임시 저장점을 설정합니다.
* `ROLLBACK TO 이름;`: 전체를 취소하지 않고 지정한 `SAVEPOINT` 시점까지만 부분적으로 복원합니다.


## 5. 내용 자세히 및 실전 예제 추가

### 테이블 생성 및 컬럼 데이터 타입 / 제약 조건 상세 개념 설명
데이터베이스에 데이터를 저장하기 위해서는 사전에 표 형태의 구조인 **테이블(Table)**을 정의해야 합니다. 이때 각 컬럼에 어떤 형태의 데이터가 들어갈지 **데이터 타입(도메인 무결성)**을 지정하고, 잘못된 데이터가 들어오는 것을 막기 위해 **제약 조건(Constraints)**을 설정합니다.
- **주요 제약 조건**: 
  - `NOT NULL`: 필수 입력 (빈 값 허용 안 함)
  - `UNIQUE`: 중복 값 허용 안 함 (고유값 유지)
  - `PRIMARY KEY`: 테이블의 각 행을 유일하게 식별하는 기본 키 (중복 불가 + `NOT NULL`)
  - `FOREIGN KEY`: 다른 테이블의 기본 키를 참조하여 관계를 맺음 (참조 무결성 보장)
  - `DEFAULT`: 값을 입력하지 않았을 때 자동으로 들어갈 기본값 지정
  - `AUTO_INCREMENT`: 숫자를 자동으로 1씩 증가시킴 (주로 기본키에 사용)

### 실전 예제 쿼리
```sql
-- 부모 테이블: 학과 정보
CREATE TABLE IF NOT EXISTS departments (
    department_id INT AUTO_INCREMENT PRIMARY KEY COMMENT '학과 번호',
    department_name VARCHAR(50) NOT NULL UNIQUE COMMENT '학과 이름'
) DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_bin COMMENT='학과 테이블';

-- 자식 테이블: 학생 정보 (참조키 및 ENUM 활용)
CREATE TABLE IF NOT EXISTS students (
    student_id INT AUTO_INCREMENT PRIMARY KEY COMMENT '학생 번호',
    student_name VARCHAR(50) NOT NULL COMMENT '학생 이름',
    email VARCHAR(100) UNIQUE COMMENT '이메일 주소',
    gender ENUM('M', 'F') NOT NULL COMMENT '성별 (M: 남, F: 여)',
    department_id INT COMMENT '소속 학과 번호',
    enrolled_date DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '입학일시',
    CONSTRAINT fk_student_department 
        FOREIGN KEY (department_id) REFERENCES departments(department_id)
        ON DELETE SET NULL ON UPDATE CASCADE
) DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_bin COMMENT='학생 테이블';

```

### DBML 상세 개념 설명

**DBML**은 데이터베이스의 구조(Schema)를 가볍고 읽기 쉬운 텍스트 형식으로 정의할 수 있는 마크업 언어입니다.

* **장점**: Git과 같은 버전 관리 시스템에서 이력 관리가 매우 쉽고, 다양한 도구를 통해 시각적인 ERD(개체-관계 다이어그램)로 자동 변환할 수 있습니다.
* **주요 표기법**:
* `[pk]`: 기본키 지정
* `[increment]`: 자동 증가
* `[not null]`: 필수 입력
* `[unique]`: 고유값
* `[default: 값]`: 기본값 지정 (문자열은 쌍따옴표 사용)
* `[ref: > 테이블명.컬럼명]`: 외래키(참조) 관계 설정 (`>` 기호는 1대다 관계를 의미)



### DBML 실전 예제 (Enum 및 외래키 연동 포함)

```dbml
-- 1. 열거형(Enum) 정의 (값마다 개별 note 지정)
Enum gender_type {
    M [note: "남성"]
    F [note: "여성"]
}

-- 2. 부모 테이블 정의: 학과 정보
Table departments {
    department_id int [pk, increment, note: "학과 번호"]
    department_name varchar(50) [not null, unique, note: "학과 이름"]
    
    note: "학과 테이블"
}

-- 3. 자식 테이블 정의: 학생 정보 (참조키 및 Enum 타입 사용)
Table students {
    student_id int [pk, increment, note: "학생 번호"]
    student_name varchar(50) [not note, note: "학생 이름"]
    email varchar(100) [unique, note: "이메일 주소"]
    gender gender_type [not null, note: "성별"]
    department_id int [ref: > departments.department_id, note: "소속 학과 번호"]
    enrolled_date datetime [default: `CURRENT_TIMESTAMP`, note: "입학일시"]

    note: "학생 테이블"
}

```

### 트랜잭션 제어 실전 예제

```sql
-- 트랜잭션 시작
START TRANSACTION;

-- 1. 새로운 주문 생성 작업
INSERT INTO orders (customer_id, order_date, status) 
VALUES (101, NOW(), 'PENDING');

-- 2. 주문 상세 내역 추가 작업
INSERT INTO order_items (order_id, product_id, quantity) 
VALUES (LAST_INSERT_ID(), 5, 2);

-- 3. 상품 재고 차감 작업
UPDATE products 
SET stock = stock - 2 
WHERE product_id = 5;

-- 모든 작업이 정상적으로 완료된 경우 확정
COMMIT;

-- 도중에 문제가 발생한 경우 모든 변경사항 취소
-- ROLLBACK;
```

## 6. 마무리 요약

* **테이블 생성과 제약 조건**: `PRIMARY KEY`, `FOREIGN KEY`, `ENUM` 등을 올바르게 설계해야 안전한 데이터베이스의 기틀이 마련됩니다.
* **DBML**: 텍스트 기반으로 복잡한 스키마와 외래키 관계, 열거형을 직관적으로 문서화할 수 있는 강력한 도구입니다.
* **트랜잭션(ACID)**: 금융 거래나 쇼핑몰 결제와 같이 데이터 신뢰성이 생명인 환경에서는 반드시 트랜잭션 제어 문법을 활용하여 데이터 유실과 불일치를 방지해야 합니다.
