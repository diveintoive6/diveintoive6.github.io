이번 포스팅에서는 다른 SQL 문 내부에 중첩되어 사용되는 **서브쿼리(Sub Query)**의 다양한 유형과 특징, 그리고 MariaDB/MySQL 환경에서 데이터베이스를 생성하고 관리하며 백업 및 복원하는 명령어에 대해 실전 활용 예제를 포함하여 정리해 보겠습니다.

---

## 1. 서브쿼리(Sub Query) 상세 개요

서브쿼리란 **다른 SQL문 내부에 중첩되어 사용되는 `SELECT`문**을 의미합니다. 메인 쿼리가 실행되기 전에 괄호 안의 서브쿼리가 먼저 실행되어 그 결과를 메인 쿼리에 전달하는 방식으로 동작합니다.

- **주요 용도**: 조건 비교, 동적 값 추출, 데이터 필터링, 집계 기준 제공 등
- **반환 형태**: 서브쿼리는 유형에 따라 단일 값, 여러 행의 리스트, 혹은 가상의 테이블(행과 열의 집합) 형태로 결과를 반환할 수 있습니다.
- **성능 관련 주의사항**: 서브쿼리는 쿼리 가독성을 높여주지만, 일반적으로 처리 속도가 `JOIN` 방식보다 느린 경우가 많습니다. 따라서 동일한 결과를 `JOIN`으로 표현할 수 있다면 가급적 `JOIN`을 사용하는 것이 성능 측면에서 더 바람직합니다.

---

## 2. 서브쿼리의 유형별 상세 분석

서브쿼리는 사용되는 위치와 반환하는 결과의 형태에 따라 크게 세 가지로 분류됩니다.

### ① 중첩 서브쿼리 (WHERE절 서브쿼리)
`WHERE`절에서 조건 비교를 위해 사용되는 서브쿼리로, 반환되는 행의 개수에 따라 다시 두 가지로 나뉩니다.
* **단일행 서브쿼리 (Single-Row Subquery)**
  - 서브쿼리의 결과가 **단 하나의 행(1행 1열)**으로 도출되는 경우입니다.
  - 메인 쿼리의 값과 비교하기 위해 일반 비교 연산자(`=`, `!=`, `<`, `<=`, `>`, `>=`)를 사용합니다.
  - *예시*: 전체 평균 급여보다 많은 급여를 받는 직원을 조회할 때 사용합니다.
* **다중행 서브쿼리 (Multi-Row Subquery)**
  - 서브쿼리의 결과가 **여러 개의 행**으로 도출되는 경우입니다.
  - 여러 값 중 하나와 일치하는지 여부를 판단해야 하므로 **`IN` 또는 `NOT IN` 연산자**를 반드시 함께 사용해야 합니다.

### ② 인라인 뷰 (FROM절 서브쿼리)
`FROM`절 내부에 `SELECT`문을 작성하여 그 결과 집합을 **임시 테이블(가상 테이블)처럼 사용하는 방식**입니다.
- **필수 조건**: 인라인 뷰로 사용되는 서브쿼리에는 **반드시 별칭(Alias)**을 지정해야 합니다.
- **특징**: 메인 쿼리는 이 인라인 뷰를 대상으로 다시 검색, 조인, 집계 등의 연산을 수행할 수 있습니다. 다만, 결과 데이터가 너무 많을 경우 전체 시스템 성능에 부담을 줄 수 있으므로 주의가 필요합니다.

### ③ 스칼라 서브쿼리 (SELECT절 서브쿼리)
`SELECT`절에 포함되는 단일행 서브쿼리입니다.
- **특징**: `SELECT`절 안에서 실행되어 **각 행마다 단일 값(1행 1열)**을 반환합니다. 메인 쿼리의 각 행이 출력될 때마다 서브쿼리가 호출되는 형태를 띱니다.
- **주의사항**: 반드시 하나의 컬럼과 하나의 행만 조회되어야 합니다.
- **성능 비교 (비상관 vs 상관 서브쿼리)**:
  - **비상관 서브쿼리**: 메인 쿼리의 컬럼을 참조하지 않으므로, 서브쿼리의 실행 결과가 모든 행에 대해 동일하여 단 한 번만 실행된 뒤 값이 재사용됩니다.
  - **상관 서브쿼리**: 서브쿼리가 메인 쿼리의 원래 테이블 컬럼(속성)을 참조하므로, 메인 쿼리의 각 행마다 개별적으로 연산을 수행합니다. 이 경우 인덱스(Index) 설계가 성능에 지대한 영향을 미치며, 대개의 경우 동일한 목적의 `JOIN` 문으로 변경하는 것이 훨씬 더 빠릅니다.

## 3. 데이터베이스 관리 및 운영 (생성, 권한, 백업, 복원)

### ① 데이터베이스 생성 및 문자셋(Character Set) 설정
데이터베이스를 생성할 때는 데이터를 저장하는 문자 집합과 정렬 규칙을 명시하는 것이 중요합니다.
```sql
CREATE DATABASE [IF NOT EXISTS] 데이터베이스이름
[DEFAULT CHARSET 캐릭터셋 COLLATE 콜레이션];

```

* **주요 캐릭터셋 비교**:
* `EUCKR`: 한글 표현용 (2바이트, 옛날 시스템 호환용)
* `utf8mb3`: MariaDB/MySQL의 구버전 3바이트 UTF-8 (일부 이모지 등 문자 누락 발생 가능)
* **`utf8mb4` (권장)**: 이모지를 포함한 진정한 전체 유니코드를 지원하는 최신 표준 캐릭터셋


* **주요 콜레이션(정렬 규칙) 비교**:
* `캐릭터셋이름_general_ci`: 대소문자를 구분하지 않고 비교 및 정렬함 (`ci`는 Case-Insensitive)
* **`캐릭터셋이름_bin` (권장)**: 완전히 일치해야 하며 대소문자를 엄격하게 구분함 (`bin`은 Binary)


* **에러 방지 옵션**: `IF NOT EXISTS`를 추가하면 이미 존재하는 데이터베이스 이름으로 생성 명령을 내릴 때 발생하는 에러를 예방할 수 있습니다.

### ② 사용자 계정 생성 및 접근 권한 부여

보안과 데이터 무결성을 위해 데이터베이스 하나당 전용 사용자 계정을 생성하고 필요한 권한만 부여하는 것이 모범 사례입니다.

```sql
-- 1. 사용자 계정 생성
CREATE USER '아이디'@'접근허용호스트' IDENTIFIED BY '비밀번호';

```

* **접근 허용 호스트의 의미**:
* 특정 IP주소: 해당 IP를 가진 컴퓨터에서만 원격 접속 허용
* `localhost` 또는 `127.0.0.1`: 물리적으로 직접 조작하는 로컬 접속만 허용
* `%`: 모든 외부 네트워크에서의 접근 허용 (보안상 주의 필요)



```sql
-- 2. 권한 부여
GRANT ALL PRIVILEGES ON 데이터베이스이름.* TO '아이디'@'접근허용호스트';

```

* 데이터베이스 이름 뒤의 `.*`는 해당 DB에 속한 모든 객체(테이블 등)에 대한 전체 권한을 의미하며, 보안 정책에 따라 `SELECT`, `INSERT` 등 세부 권한을 나누어 부여할 수도 있습니다.

### ③ 데이터베이스 삭제

```sql
DROP DATABASE [IF EXISTS] 데이터베이스이름;

```

* 한 번 수행된 삭제 명령은 즉시 모든 데이터를 영구적으로 소실시키며 **절대 되돌릴 수 없습니다.** 따라서 `IF EXISTS` 옵션을 덧붙여 안전 장치를 마련하고 매우 신중하게 실행해야 합니다.

### ④ 데이터베이스 백업과 복원 (CLI 환경)

데이터베이스 백업 및 복원은 데이터베이스 내부 SQL 창이 아닌, **윈도우 명령 프롬프트(CMD)나 시스템 터미널 환경**에서 관리자 계정 권한으로 수행해야 합니다.

* **백업 명령어 (`mariadb-dump`)**
```bash
mariadb-dump -u사용자이름 -p [--databases] [--port=포트번호] 데이터베이스이름 > 백업파일경로

```


* `--databases` 옵션을 사용하면 백업 파일 내부에 `CREATE DATABASE` 및 `USE` 문이 포함되어 원본 구조 그대로 복원됩니다.
* 실습용 시스템 등의 포트 번호가 기본값(3306)이 아닐 경우 `--port=포트번호` 옵션을 명시해야 합니다.


* **복원 명령어 (`mariadb`)**
```bash
mariadb -u사용자이름 -p [--port=포트번호] 복원할_데이터베이스이름 < 백업파일경로

```


* 성공적으로 실행될 경우 별도의 성공 메시지 없이 조용히 완료되며, 백업 파일 생성 시 사용한 옵션에 따라 복원 대상 DB 설정이 연동됩니다.

## 4. 실전 활용 예제 10선

### 예제 1: 단일행 서브쿼리를 이용한 평균 급여 이상 직원 조회 (`WHERE`)

전체 직원의 평균 급여보다 더 많은 급여를 받는 직원들을 조회합니다.

```sql
SELECT employee_name, salary
FROM employees
WHERE salary > (SELECT AVG(salary) FROM employees);

```

### 예제 2: 다중행 서브쿼리를 이용한 특정 부서 소속 직원 조회 (`IN`)

기획부와 개발부에 속한 부서 ID를 가진 직원들을 조회합니다.

```sql
SELECT employee_name, department_id
FROM employees
WHERE department_id IN (SELECT id FROM departments WHERE department_name IN ('기획부', '개발부'));

```

### 예제 3: 인라인 뷰(FROM절 서브쿼리)를 이용한 파생 테이블 검색

부서별 평균 급여를 먼저 계산한 뒤, 그 결과 테이블에서 평균 급여가 400만 원 이상인 부서만 다시 필터링합니다.

```sql
SELECT dept_avg.department_id, dept_avg.avg_sal
FROM (
    SELECT department_id, AVG(salary) AS avg_sal
    FROM employees
    GROUP BY department_id
) AS dept_avg
WHERE dept_avg.avg_sal >= 4000000;

```

### 예제 4: 스칼라 서브쿼리(SELECT절 서브쿼리) 활용

직원 목록을 조회할 때, 각 직원의 소속 부서명을 스칼라 서브쿼리로 함께 가져옵니다.

```sql
SELECT employee_name, salary,
       (SELECT department_name FROM departments WHERE departments.id = employees.department_id) AS dept_name
FROM employees;

```

### 예제 5: utf8mb4 캐릭터셋과 bin 콜레이션을 적용한 DB 생성

이모지와 대소문자를 엄격하게 구분하는 실무형 데이터베이스를 생성합니다.

```sql
CREATE DATABASE IF NOT EXISTS shop_db
DEFAULT CHARSET utf8mb4 COLLATE utf8mb4_bin;

```

### 예제 6: 전용 사용자 계정 생성 및 로컬 접속 권한 부여

쇼핑몰 DB를 관리할 전용 계정을 생성하고 비밀번호를 설정합니다.

```sql
CREATE USER 'shop_admin'@'localhost' IDENTIFIED BY 'SecurePassword123!';

```

### 예제 7: 특정 데이터베이스에 대한 모든 권한 부여 (`GRANT`)

생성한 사용자에게 해당 쇼핑몰 DB에 대한 모든 제어 권한을 부여합니다.

```sql
GRANT ALL PRIVILEGES ON shop_db.* TO 'shop_admin'@'localhost';

```

### 예제 8: 안전한 데이터베이스 삭제 구문 작성 (`DROP DATABASE`)

실수로 인한 에러를 막기 위해 존재할 때만 삭제하도록 안전장치를 포함합니다.

```sql
DROP DATABASE IF EXISTS test_db;

```

### 예제 9: 터미널 환경에서의 데이터베이스 백업 실행 예시

지정된 포트(9090)와 관리자 계정을 사용하여 특정 DB를 파일로 백업합니다.

```bash
mariadb-dump -uroot -p --port=9090 shop_db > C:\\backup\\shop_db_backup.sql

```

### 예제 10: 백업 파일로부터 데이터베이스 복원 실행 예시

백업된 SQL 파일을 지정한 데이터베이스에 다시 불러와 복원합니다.

```bash
mariadb -uroot -p --port=9090 shop_db < C:\\backup\\shop_db_backup.sql

```

## 5. 마무리 요약

* **서브쿼리**는 쿼리를 구조화하는 데 유용하지만, 대용량 데이터 환경에서는 성능 저하를 유발할 수 있으므로 가능하면 `JOIN`으로 대체하는 습관이 좋습니다.
* **데이터베이스 관리 및 백업/복원**은 서비스 운영 시 데이터 유실을 방지하기 위한 필수 기술이므로 덤프 명령어(`mariadb-dump`)의 사용법을 잘 숙지해 두어야 합니다.
