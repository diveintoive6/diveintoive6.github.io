파이썬에서 `@property`를 이용해 캡슐화와 데이터 검증(Getter/Setter)을 구현할 때, 가장 흔하게 저지르는 실수 중 하나가 바로 내부 변수 이름을 프로퍼티 이름과 똑같이 짓는 것입니다.

만약 `self.__가창력` 대신 `self.가창력`을 쓰게 되면 어떻게 될까요? 단순히 구분을 못 하는 것을 넘어, 프로그램이 **무한 재귀(Infinite Recursion) 에러**로 터지게 됩니다.

---

## 1. 무한 루프가 발생하는 이유

getter 함수 내부에서 자기 자신인 프로퍼티를 다시 호출할 때 발생하는 문제를 코드로 살펴보겠습니다.

### ❌ 잘못된 코드 (무한 루프 발생)

```python
@property
def 가창력(self):
    return self.가창력  # 🚨 여기서 self.가창력은 내부 변수가 아니라 '프로퍼티 자체'를 다시 호출하는 것임!

```

### 🔄 호출 흐름 (메모리 폭발 과정)

1. 외부에서 `아이브.가창력`을 호출합니다.
2. 파이썬은 `@property`로 정의된 `가창력(self)` 함수를 실행합니다.
3. 함수 안에서 `return self.가창력`을 만나는 순간, **자기 자신인 `가창력` 프로퍼티를 또다시 호출**합니다.
4. 2번과 3번 과정이 끝없이 반복되면서 메모리 한계치를 초과하게 됩니다.

**출력되는 에러 메시지:**

```text
RecursionError: maximum recursion depth exceeded

```

---

## 2. 올바른 구조: 프로퍼티와 내부 변수의 분리

이러한 문제를 해결하기 위해 파이썬에서는 "외부에서 보이는 이름(인터페이스)"과 "실제 데이터가 저장되는 공간(내부 변수)"을 다르게 분리합니다.

```python
@property
def 가창력(self):
    return self.__가창력  # ✅ 진짜 데이터가 들어있는 숨겨진 공간을 리턴해야 함!

@가창력.setter
def 가창력(self, 값):
    if 값 < 0:
        값 = 0
    self.__가창력 = 값  # ✅ 숨겨진 공간에 값을 저장

```

* **외부 사용자:** `아이브.가창력 = 200` 또는 `print(아이브.가창력)`처럼 **공개된 이름**으로 접근합니다. (이때 파이썬이 알아서 `@property`와 `@setter`를 가로채어 작동시킵니다.)
* **클래스 내부:** 혼동을 막고 무한 루프를 방지하기 위해 언더바 두 개(`__`)가 붙은 비공개용 내부 변수(`self.__가창력`)에 직접 값을 넣고 가져옵니다.

---

## 3. 한눈에 보는 비교 정리

| 구분 | 공개용 (프로퍼티) | 비공개용 (내부 변수) |
| --- | --- | --- |
| **형태** | `self.가창력` | `self.__가창력` |
| **역할** | 외부에서 접근하는 창구 (Getter/Setter와 연결) | 실제 값이 안전하게 저장되는 진짜 데이터 공간 |
| **사용 위치** | 외부 호출 및 `__init__`, 메서드 등 | `@property` 및 `@setter` 내부 로직 |
| **주의점** | Getter 안에서 사용하면 **무한 루프 발생** | 외부에서 직접 접근 지양 (정보 보호) |
