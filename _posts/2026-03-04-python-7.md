파이썬에서 데이터를 모아 담는 가장 대표적인 3가지 바구니는 **리스트(List)**, **튜플(Tuple)**, 세트(Set)입니다. 각각의 성격과 성능(생성 속도, 검색 속도 등)에서 뚜렷한 차이를 보입니다.

---

## 1. 한눈에 보는 비교 표

| 특징 | 리스트 (List) | 튜플 (Tuple) | 세트 (Set) |
| --- | --- | --- | --- |
| **기호** | 대괄호 `[ ]` | 소괄호 `( )` | 중괄호 `{ }` |
| **변경 가능성 (Mutability)** | **가변** (값 수정, 추가, 삭제 가능) | **불변** (한번 만들면 수정 불가) | **가변** (요소 추가/삭제 가능, 단 요소는 불변만 허용) |
| **순서 (Order)** | 있음 (넣은 순서 유지) | 있음 (넣은 순서 유지) | **없음** (순서가 뒤죽박죽) |
| **중복 허용** | 허용 (`[1, 2, 2]`) | 허용 (`(1, 2, 2)`) | **허용 안 함** (고유값만 유지, `{1, 2}`) |
| **인덱싱 / 슬라이싱** | 가능 (`a[0]`) | 가능 (`a[0]`) | **불가능** (순서가 없으므로 인덱스 번호 없음) |
| **생성 속도** | 보통 (메모리 공간 여유분 할당) | **매우 빠름** (고정 크기로 가볍게 생성) | 느림 (해시 테이블 구성 및 중복 검사 비용 발생) |
| **인덱스로 값 조회** | 매우 빠름 ($O(1)$) | 매우 빠름 ($O(1)$) | **불가능** (인덱스 없음) |
| **값 존재 확인 (`in`)** | 느림 ($O(N)$ - 처음부터 끝까지 탐색) | 느림 ($O(N)$ - 처음부터 끝까지 탐색) | **매우 빠름** ($O(1)$ - 해시 기반 검색) |

## 2. 각 자료구조의 상세 특징

### ① 리스트 (List) — "줄 세워진 대기열 (수정 가능)"

* 데이터를 순서대로 저장하며, 언제든지 값을 바꾸거나 추가(`append`), 삭제할 수 있습니다.
* **주요 용도:** 데이터의 순서가 중요하고, 항목이 동적으로 늘어나거나 줄어들 때 사용합니다. (예: 쇼핑몰 장바구니, 게시글 목록)

### ② 튜플 (Tuple) — "밀봉된 읽기 전용 상자"

* 리스트와 비슷하게 순서가 있지만, **한 번 만들면 내부를 절대 수정할 수 없습니다.** (추가, 삭제, 변경 불가능)
* **성능 특징:** 값이 변하지 않기 때문에 파이썬 내부적으로 최적화가 잘 되어 있어, 작은 크기의 데이터일 경우 리스트보다 **생성 속도가 훨씬 빠르고 메모리를 적게 차지**합니다.
* **주요 용도:** 절대 바뀌면 안 되는 설정값이나 좌표(`(latitude, longitude)`) 등을 표현할 때 사용합니다.

### ③ 세트 (Set) — "중복 없는 주머니 (집합)"

* 순서가 없고, **오직 유일한 값(Unique)만** 담을 수 있습니다.
* **성능 특징:** 내부적으로 **해시 테이블(Hash Table)** 구조로 이루어져 있어, 특정 값이 주머니 안에 들어있는지 확인할 때(`x in my_set`) 리스트나 튜플과 비교할 수 없을 정도로 **압도적으로 빠릅니다 ($O(1)$)**.
* **주요 용도:** 데이터 중복 제거, 포함 여부 검사(`in`), 수학적 집합 연산(합집합, 교집합, 차집합)이 필요할 때 사용합니다.

---

## 3. 성능(속도) 관점의 깊이 있는 이해

### 🚀 1. 생성 속도 (Creation Speed)

* **`Tuple` > `List` > `Set**`
* **튜플**은 불변이기 때문에 파이썬이 메모리를 고정 크기로 한 번에 딱 할당하고 끝내어 생성 속도가 가장 빠릅니다.
* **리스트**는 나중에 요소가 추가될 것을 대비해 여유 공간(Over-allocation)을 두고 메모리를 관리하므로 튜플보다는 생성 속도가 살짝 느립니다.
* **세트**는 데이터를 넣을 때마다 중복인지 검사하고 해시 값(Hash value)을 계산하는 과정이 들어가므로 생성 비용이 가장 큽니다.

### 🔍 2. 값 찾기 속도 (`in` 연산)

* **`Set` (압도적으로 빠름, $O(1)$) >>> `List` / `Tuple` (느림, $O(N)$)**
* **리스트와 튜플**은 안에 값이 있는지 확인하려면 첫 번째 원소부터 마지막 원소까지 하나씩 차례대로 대조하며 찾아야 합니다(`Linear Search`). 데이터가 100만 개면 최대 100만 번을 뒤져야 합니다.
* **세트**는 해시 주소를 이용해 단 한 번에 위치를 찾아내기 때문에 데이터가 수백만 개여도 눈 깜짝할 사이에 결과를 찾아냅니다.

## 4. 실전 코드 예시

```python
# 1. 리스트: 순서 유지, 중복 허용, 값 변경 가능
my_list = [1, 2, 2, 3]
my_list[0] = 99  # 수정 가능
print(my_list)   # 출력: [99, 2, 2, 3]

# 2. 튜플: 순서 유지, 중복 허용, 값 변경 불가(에러 발생)
my_tuple = (1, 2, 2, 3)
# my_tuple[0] = 99  # ❌ TypeError 발생!
print(my_tuple[0]) # 인덱스 조회는 가능 -> 출력: 1

# 3. 세트: 순서 없음, 중복 자동 제거, 인덱스 접근 불가
my_set = {1, 2, 2, 3, 3, 3}
print(my_set)    # 출력: {1, 2, 3} (중복 자동 삭제)
# print(my_set[0]) # ❌ TypeError 발생! (인덱싱 불가)

# 속도 차이 체감 (포함 여부 확인)
large_list = list(range(1000000))
large_set = set(range(1000000))

# 999999가 있는지 찾을 때
# print(999999 in large_list)  # 리스트: 전체를 다 뒤지므로 눈에 띄게 느림
# print(999999 in large_set)   # 세트: 해시로 즉시 찾으므로 0초에 가까움

```
