앞서 동기/비동기와 블로킹/논블로킹의 개념을 살펴보았습니다. 그중 **비동기(Asynchronous)** 방식은 요청한 순서대로 결과가 끝난다는 보장이 없기 때문에, 작업이 끝난 후의 처리를 다루는 방법이 매우 중요합니다.

자바스크립트가 비동기 처리의 한계를 극복하기 위해 어떤 방식으로 진화해 왔는지 그 과정을 정리해 보았습니다.

---

## 1. 비동기 처리의 기본: 순서가 보장되지 않는다

* **동기 (Synchronous):** 1번이 끝나야 2번을 시작하고, 2번이 끝나야 3번을 시작하므로 `1 -> 2 -> 3` 순서와 결과가 완벽히 일치합니다.
* **비동기 (Asynchronous):** 1, 2, 3번 작업을 동시에 요청해 버리기 때문에, 각 작업이 걸리는 시간에 따라 끝나는 순서가 뒤죽박죽이 됩니다. (예: 3번이 먼저 끝나서 결과가 먼저 올 수도 있습니다.)

따라서 비동기 환경에서는 **"작업이 끝나는 대로 먼저 끝나는 녀석의 결과를 처리"**해야 하며, 이를 위해 등장한 개념이 바로 **콜백(Callback)**입니다.

---

## 2. 콜백(Callback) 함수와 한계 (콜백 지옥)

* **개념:** *"이 작업 다 끝났으면, 준비된 그 결과 가지고 네가 지정해 둔 이 함수(콜백)를 실행해 줘"* 하고 비동기 함수에 던져두는 함수입니다.
* **동작 방식:** 먼저 끝나는 작업의 콜백이 순서에 상관없이 끝나는 대로 먼저 호출됩니다. (예: 2초 걸리는 1번 작업보다 1초 걸리는 2번 작업의 콜백이 먼저 실행됨)
* **문제점:** 비동기 작업의 결과에 의존해 또 다른 비동기 작업을 계속 호출해야 할 때, 코드가 안으로 파고드는 **'콜백 지옥(Callback Hell)'**이 발생하여 가독성이 심각하게 떨어집니다.

```javascript
// 콜백 지옥 예시
getData(function(a) {
    getMoreData(a, function(b) {
        getEvenMoreData(b, function(c) {
            // 코드가 우측으로 꺾이며 유지보수가 힘들어짐
        });
    });
});

```

---

## 3. Promise (프로미스)의 등장

* **개념:** *"비동기 작업의 '결과'를 미래에 반드시 주겠다고 약속(Promise)하는 객체"*입니다.
* **상태(State) 개념:**
* **Pending (대기):** 비동기 작업이 아직 진행 중인 상태
* **Fulfilled (이행):** 작업이 성공적으로 끝나서 결과값을 반환한 상태
* **Rejected (거부):** 작업이 실패하거나 에러가 난 상태


* **특징:** `.then()`이나 `.catch()` 같은 체이닝(Chaining) 방식을 제공하여, 콜백 지옥 없이 "이거 성공하면 다음 거 해 줘" 하는 형태로 순서를 깔끔하게 연결할 수 있게 되었습니다.

---

## 4. async / await (에이싱크 / 어웨이트)

* **개념:** Promise를 마치 동기 코드처럼 자연스럽고 읽기 쉽게 작성할 수 있게 해주는 문법 설탕(Syntactic Sugar)입니다.
* **키워드 역할:**
* `async`: 함수 앞에 붙이며, 이 함수는 항상 Promise를 반환한다는 것을 명시합니다.
* `await`: Promise가 처리될(성공하든 실패하든 끝날) 때까지 기다리게 만듭니다. *(단, 전체 프로그램이 멈추는 블로킹이 아니라, 해당 비동기 함수 안에서만 잠시 기다리는 논블로킹 방식으로 동작합니다.)*


* **특징:** 비동기 코드임에도 불구하고 위에서 아래로 흐르는 동기 코드처럼 작성할 수 있어, 가독성이 극대화됩니다.

### 📌 코드 비교: Promise vs Async/Await

#### [Promise 체이닝 방식]

```javascript
function processData() {
    getData()
        .then(a => getMoreData(a))
        .then(b => getEvenMoreData(b))
        .then(c => {
            console.log(c);
        })
        .catch(error => {
            console.error(error);
        });
}

```

#### [Async / Await 방식 (훨씬 직관적)]

```javascript
async function processData() {
    try {
        const a = await getData();
        const b = await getMoreData(a);
        const c = await getEvenMoreData(b);
        console.log(c); // 동기 코드처럼 편안하게 작성 가능!
    } catch (error) {
        console.error(error);
    }
}

```

---

## 💡 요약

* **비동기 작업은 끝나는 순서가 제각각**이므로 결과를 받기 위해 **콜백**을 사용했습니다.
* 콜백의 복잡함을 해결하기 위해 **Promise**가 체이닝 구조를 만들었고,
* 이를 다시 완벽한 동기 코드 형태로 읽기 쉽게 만들어 준 것이 바로 **async/await**입니다.
